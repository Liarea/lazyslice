# ADR-015: A residual hit inside the name masker's own vocabulary is explained by count and row identity, not confirmed by a column probe

Status: proposed, 2026-09-22. Narrows one clause of ADR-005 (the residual scan's confirmation, ARCHITECTURE.md section 6 item 3) for exactly one category, `person_name`, and records one type addition to section 2's `Residual`. ADR-005 and ADR-006 are accepted and frozen and stand otherwise; this is a new record, not an edit (root CLAUDE.md).

## Context

The maintainer decided on 2026-09-22 that masked given names and surnames are real, common names from a public top-500 list, not the made-up syllable tokens T-0287's fix round introduced (T-0292, the open product call). The reason those tokens exist is not taste. ARCHITECTURE.md section 6 item 3, as built in `internal/verify/residual.go`, confirms a residual hit by asking whether the source *column* holds the value anywhere (`confirm`, two probes, indexable form first), and `handle` turns the first confirmed hit into exit 9. On an ordinary customers table a masked "Mary" is some other customer's real "Mary", so a real-name list refuses the run on its first use; T-0287's own fix round measured it on Pagila, where 27 of 141 hand-listed given names were literal values of `customer.first_name`. The size of the list is not the lever: any real corpus over any real column of a few hundred rows produces a confirmed hit, and one is enough.

THREAT_MODEL.md T12 makes the residual scan the one check on the masker itself, and `maskCell`'s comment (T-0191) defers a keyed self-draw, the masker returning its input by chance, to that same scan. Root CLAUDE.md: safety rails are not configurable away; never a flag that disables masking; when in doubt, mask.

The design below was produced by two independent proposals, each attacked by three skeptics (a red-teamer, a maintainer who fears a silent false negative, an implementer), and synthesised from what survived (orchestrator's record, 2026-09-22).

## Options considered

**(A) A row-keyed check replacing the column probe for `person_name` and `address`, with a redraw in `mask.Apply`.** The probe asks whether the *same row* in the source, matched on the primary key the target carries verbatim, holds the value; a no is a coincidence. Refuted: it passes any leak that moves a real value from one row to another (a registered masker drawing from an exported real-name list, a transform or load batch shift, an in-row array rotation), all of which today's column probe catches; its redraw sat before `tracksItsInput`, so a partial-passthrough masker would be laundered instead of refused; and it widened the exemption to `address`, a category the maintainer did not ask for.

**(B) A vocabulary test plus a transform-side count of emitted cells, no key and no probe in verify.** A hit is explained when the value is one the masker's own list contains and the target holds it no more often than transform emitted it. Refuted on one point only: it accepted the keyed fixed point `f(u) = u`, a masker drawing, under a shared key, the very name it was given, which ships a cohort's real names permanently; the comment it cited (T-0191) says the residual scan is the check on that case.

**(C) B's rail, plus A's redraw moved after the passthrough guard and limited to the vocabulary masker, plus A's identity join demoted to a bounded second confirmation where a row identity exists.** The two refutations point in opposite directions, which is the sign the answer is the combination.

**(D) Keep the column probe and document the refusal** (T-0292's second option). Rejected: it makes the demo refuse itself on Pagila and puts the operator's way out at `--take`, which is documentation as the fix for a confusing first run.

## Decision

(C). Per hit in a masked column, the residual scan does the following; every branch not named keeps today's behaviour.

1. **Vocabulary gate.** `mask.Emits(id, value, constraints)` answers whether the masker could have produced this value for this column. It is backed by an unexported method on the masker type, so only a masker inside package `mask` can answer true; a registered custom masker, an unknown id, a `fixed:` id, an equality-group escalation and every label-constrained column answer false. Only `personNameMasker` implements it, over the lists it draws from, testing membership after the category's canonical fold. A masker may implement the method only if canonical equality with an input implies letters-and-digits fold equality with that input's canonical form, which is why `person_name` qualifies and phone, date, national identifiers and email do not. A hit `Emits` rejects takes today's path unchanged: indexable probe, folded probe, exit 9 when confirmed.

2. **Count check.** transform records, for every masked cell of an emitting column (scalars and array elements, never a JSON leaf), one count against `HMAC(runKey, enc("emitted", column, path, canonical(output)))` (`Residual.AddEmitted`; a mutex-guarded map from the truncated HMAC to a count, so nothing here stores a value). verify tallies the target's occurrences of each hit value per column and requires each to be at most what transform emitted. A value the target holds more often than the masker produced it goes through today's `handle` on one retained target value: a probe, and exit 9 `verify.refused.residual` when the source holds it, with a new fixed reason. This needs no key and no row identity in verify and no source read for an explained value, so it works identically on a table without a primary key.

3. **Self-avoiding masker.** In `maskCell`, after `looksLikeItsInput` fires and after `tracksItsInput` has run and passed (a masker that follows its input is still `ErrPassthrough`, exit 7, before any redraw can launder it), a masker that implements the vocabulary method is redrawn under `h_i = SHA-256(h || "lazyslice/redraw" || i)`, i = 1..8, until the output no longer reads as its input. Output stays a pure function of the key, the category, the canonical value and the constraints, so determinism, foreign-key equality groups and byte-identical reruns (invariant I3) hold. After this a value that fold-equals its own row's source value can reach the target only through a bypass, and a bypass adds a target occurrence the masker never emitted, so step 2 refuses it: the two layers no longer defer to each other.

4. **Row-keyed second check.** For tallied hits in a scalar column of a table with a usable identity (the step's identity columns when the plan knows them unique, a primary key or unique rung, or the primary key of a lookup step; every identity column unmasked and joinable, as `sample.go` already requires), verify keeps the row's identity tuple and sends each batch of at most 1,000 identities as it fills during the scan, so it holds one batch per column rather than the column's rows, through the existing typed-unnest join (allowlisted as `verify.rowcheck.<table>`), fetching the identity columns and the source column. Any row whose source value is canonical-equal or fold-equal to that row's target value is exit 9 with a second fixed reason. A pseudo-key, or an explicit `--key` probed only on a sample, is no usable identity: two rows sharing it would compare one row's source value against another row's target value, which both passes a same-row leak and refuses a correct run (T-0302's review round). A row that is absent, an identity with a NULL part, or a table with no usable identity learns nothing more: the count check already stands, and there is no fallback to the column probe, because that fallback is what would refuse a correct run. The candidate value is never bound; only identifiers the target already holds verbatim travel to the source.

5. **Report.** One line per column, `verify.residual.explained`, passing, count only: how many masked values equal a real value elsewhere in this column, that the list contains each, that the masker produced every copy, and that no row kept its own. Never a value.

6. **Cost.** An explained hit spends no probe; an over-count value spends up to two, as today. A row-check statement does not spend `--residual-probe-cap`: the cap bounds statements that bind a candidate value, which lands in the source's log, and that may be a sequential scan, and a row check does neither; there is one per 1,000 rows holding a tallied value, which the target's own size bounds, and sharing the cap would refuse a large correct run (500,000 people with two name columns is 1,000 statements). On Pagila's customer table a correct run sends about one row-check statement per name column and no probe; under today's rule it would spend about 1,200 probes and reach the probe cap before it reached exit 9.

What stays strict, unchanged: every category but `person_name` (email, phone and network identifiers keep their reserved ranges as stated limit 13; address keeps both its forms; every other category keeps the column probe); every equality-group escalation; every custom, unknown or `fixed:` masker; a `person_name` value off the list, a full name in a given-name column, a label-constrained name column; any value with more target copies than transform counted; every JSON leaf and key hit; a masked array literal that will not split; `ErrPassthrough` at exit 7; the probe cap on confirmation probes, and the source-closed and probe-failed refusals. No flag is added: the exemption is the mask module's structure, not configuration.

Where the proposals disagreed, this record took B's structure (count, no probe for an explained value) over A's (identity as the verdict), because a real value that moved between rows must still be caught; and took A's redraw over B's silence on the fixed point, because the residual scan can no longer be the check on a self-draw once it explains coincidences.

## Consequences

- Pagila and any ordinary customers table pass under a real-name list; the report says how many masked names equal a real one elsewhere in the column.
- A masked person name never equals its own source value, which reveals about 1/500 of a bit per value; THREAT_MODEL.md T12 carries this.
- The one uncaught case narrows to a fault that both copied one row's listed real name into another row and lost the masked copy of that same name from the same column, on a table without a usable row identity; with an identity the row check catches it.
- `Residual` gains `AddEmitted` and `Emitted` (ARCHITECTURE.md section 2, "type additions recorded after implementation"); section 6 items 3 and 6, THREAT_MODEL.md T12 with T1's pointer, SECURITY.md item 12, internal/verify/CLAUDE.md (a Never line: never let a hit outside `mask.Emits` skip the column probe; never read an unanswered row check as a coincidence; never fall back from the row check to the column probe), mask/CLAUDE.md and internal/transform/CLAUDE.md change with the landing (T-0302).
- The second net skips a generated column whose expression names only masked columns of its own table; a `full_name GENERATED ALWAYS AS (first_name || ' ' || last_name)` column would otherwise refuse every real-name run.
- Invariant I2 checks an emitting column by row identity and by vocabulary, and logs cross-row overlap instead of failing on it.
- The lists themselves are a separate decision: the 2020 Census top-500 given names per sex and top-1,000 surnames (public domain; T-0303 for the tooling, T-0304 for the switch). They must hold at least 400 words each so a name column never trips section 5's `small_domain` rule over a 200-row sample. With T-0304 every masked person name changes, named in the release notes as a 0.x minor (mask/v0.3.0, v0.3.0); T-0292 closes against that landing.
- Found while deciding, filed rather than folded in: `person_date` almost certainly refuses correct runs by the same coincidence today and needs its own rule (T-0305); a masked enum with more than 128 labels reaches the filter (T-0306).

## Reversal condition

A red-team round or a torture run shows a real value reaching the target under `verify.residual.explained` (a bypass both the count check and the row check passed), or the fold-faithfulness test for a vocabulary masker fails. Either supersedes this record: `person_name` returns to the column probe, and the real-name lists come out with it.
