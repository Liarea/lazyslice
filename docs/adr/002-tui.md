# ADR-002: Bubble Tea v2, but the default is a line printer

Status: accepted, 2026-09-05

## Context

CONCEPT.md "Terminal first": the terminal UI is a thin layer over the CLI and no capability may exist only in the TUI. CLAUDE.md: every TUI action must be reachable by a CLI flag first. docs/BUILD_PLAN.md recommends Bubble Tea and Lip Gloss, the lazygit lineage.

The proposals agreed on the framework and disagreed on when it is entered. research/proposals/mvp-first.md "D2" makes the plain renderer the default and then enters Bubble Tea "when stdin and stdout are a TTY and either a blocking question exists", which is every interactive happy-path run; the third judge called that self-defeating. research/proposals/user-first.md "2. TUI" argues from the product: "CONCEPT.md's transcript is scrollback — it survives the run and pastes into a compliance ticket; an alternate-screen app erases itself on exit." All three judges named that the strongest single argument in any proposal, and it connects to research/COMPLAINTS.md TR-10, where the gate to adoption is convincing data custodians, not the developer. research/SQLIT_STUDY.md §2.0 adds that discovery must never block the first printed line, and §2.4 that sqlit's hand-kept keybinding table has four wrong rows in eleven.

## Options considered

- **Bubble Tea as the interactive default, plain renderer for CI.** What lazygit does. Erases the transcript on exit, which is the artefact the pitch, the GIF and the compliance ticket rest on.
- **Line printer only, `$PAGER` for long tables.** Cheapest; but the classifier's reasons on a 200-column schema and the plan table on 40 tables do not fit a screen, and `?` at a prompt has nowhere to go.
- **Line printer default; Bubble Tea for the two screens that need paging.** The user-first design. Bubble Tea is entered by `--tui`, or by `?` at a prompt, and only for the classifier's reasons and the plan table; the run itself prints lines.

## Decision

The happy path is a line printer. `lazyslice` prints the transcript in CONCEPT.md, line by line, into scrollback, with a progress line that redraws in place on a TTY and prints periodically otherwise. That transcript is evidence a developer pastes into a ticket, so it must survive the run.

Bubble Tea v2 (`charmbracelet/bubbletea/v2` v2.0.9, `lipgloss/v2` v2.0.6, `bubbles/v2` v2.2.1, all verified 2026-09-05) is entered only by `--tui`, or by pressing `?` at a prompt, and only for two screens: the classification table with reasons, and the plan table. Leaving either returns to the line printer with the screen contents echoed into scrollback. The TUI owns no logic: it builds the same `core.Request` as the CLI and subscribes to the same `event.Sink` (ADR-005).

Three enforcement mechanisms, all from the research, all in phase 3:

1. `TestEveryTUIActionHasFlag` fails on any keybinding whose action has no CLI flag (research/proposals/risk-first.md "2. TUI"; research/proposals/user-first.md "5. The pipeline").
2. `docs/KEYBINDINGS.md` and the flag reference are generated from the binding and flag tables by `go generate`, with a CI check that fails on drift (research/SQLIT_STUDY.md §5.8; lazygit's arrangement).
3. Discovery never blocks the first printed line; candidates print as each verification resolves (research/SQLIT_STUDY.md §2.0, §5.1).

The footer inside the two TUI screens is computed from state, and a binding that is unavailable renders struck through rather than vanishing (research/SQLIT_STUDY.md §2.4). Cancel is not rebindable.

The event model that both renderers consume has no field able to carry a row value or a DSN (research/proposals/risk-first.md "S5"); see ADR-005 and THREAT_MODEL.md T4.

Where the judges disagreed: mvp-first reached the same default by cost ("the only one Gate 4's GIF requires"); user-first reached it from the artefact. The reason written here is the artefact's, because a reason about cost gets reversed when there is time, and this one should not be.

## Consequences

- The 20-second GIF at Gate 4 shows scrollback, not an alternate screen. If that is not impressive, the fix is better lines, not a bigger TUI.
- `--json` emits the same event stream as NDJSON, so a test can prove the TUI adds nothing.
- Bubble Tea is a phase 4 last-step dependency (docs/BUILD_PLAN.md PROMPT 4.6); nothing before it imports `internal/tui`, and `internal/core` never imports it.
- Windows console handling for the in-place progress line is a phase 5 hardening item, not a phase 4 blocker.

## Reversal condition

If, on every fixture through Gate 5, the plan table and the reasons list both fit in 40 printed lines, drop Bubble Tea for the line printer plus `$PAGER`. If dogfood sessions show users cannot find `?`, make `--tui` the TTY default. Neither reversal may move a capability into the TUI; that rule has no reversal condition.
